# Authenticate literal scalar roots and correct Case 2 Gold

## Decision

Accepted automatically under the user's standing instruction to accept project
decisions: authenticate the immutable ADR-0042 public stress Case 2 expert reads
only through a strict literal PowerShell scalar-root form, then adjudicate its
route against the package's actual owner rules before classifying the product.

Recognize the scalar form only when one literal variable is assigned exactly to
the staged relative Design references directory, every `Get-Content -Raw` path
uses that variable plus one distinct known expert basename, the completed command
has zero exit status and no wildcard, traversal, UNC or outside root, and the
captured output contains exactly one complete normalized staged body for every
read. Dynamic assignments, unknown or duplicated files, non-read mentions,
truncated or duplicated bodies, and failed commands remain fail-closed.

Preserve the original Case 2 Gold and its first failed classification. Record a
versioned replacement Gold whose exact expected route is Editorial, Composition,
Typography and Information Design, while retaining Colour and Media Production
as forbidden. Replay the immutable raw evidence only after extractor tests pass;
make no outcome retry or additional provider call.

## Problem

Case 2 read four staged experts through a literal `$p` references root, but the
extractor could not authenticate variable-expanded paths. Independent owner
inspection also shows that the original Editorial-only Gold conflicts with the
brief: it explicitly leaves fixed-page sequence, reading hierarchy, grouping,
type hierarchy and a two-page timetable open. Those concerns route respectively
to Editorial, Composition, Typography and Information Design. The test's actual
negative boundary is whether already settled reproduction and delivery work
incorrectly load Colour or Media Production.

## Drivers

- Authenticate command and captured-output evidence without trusting terminal
  self-report.
- Keep all accepted path forms staged, literal, known and fail-closed.
- Distinguish a benchmark-label defect from a package-routing defect.
- Preserve immutable raw events and original Gold for auditability.
- Avoid a provider retry when the existing response is complete.

## Considered alternatives

- Keep the original Editorial-only Gold. Rejected because it contradicts the
  brief and the package's direct expert index.
- Remove the three additional reads from the raw evidence. Rejected because raw
  events are immutable and the reads were materially justified.
- Credit terminal `selected_experts`. Rejected because self-report is diagnostic
  only.
- Accept arbitrary variable-expanded paths. Rejected because dynamic roots can
  escape the staged snapshot or make the read ambiguous.
- Rerun Case 2 with a narrower prompt. Rejected because that would be an outcome
  retry and would test a different brief.

## Consequences

- Case 2 is replayed from its original raw events against a versioned corrected
  Gold after focused adversarial tests pass.
- Passing replay proves only the intended public routing boundary and response
  contract; it does not erase the original benchmark defect.
- The route-provenance code and future executable manifests change again; v6
  remains immutable failed historical evidence.
- Case 3 remains stopped until the Case 2 replay is terminal.
- No Design package file changes from this qualification repair.
- Publication, installation, commit, push, tag and release remain unauthorized.
- W-005 was already in progress, so its immutable `Decisions` list cannot add
  ADR-0044; mutable Evidence records this adjudication.

## Confirmation

Confirm focused acceptance and adversarial tests, immutable Case 2 raw and
artifact hashes, exact four authenticated reads, zero forbidden reads, terminal
alignment, original-Gold preservation, corrected-Gold replay, zero additional
provider or sealed calls, and continued sequential stop before Case 3.

## Revisit when

Another variable or shell expansion form is proposed, the route owner rules
change, a future public case intentionally isolates Editorial from hierarchy or
table decisions, or captured command output no longer includes complete bodies.
