## What to author

Use English original synthesis in runtime instructions. Prefer one concise decision aid or worked fragment for an actual unresolved operation. The useful shape is `context and question → available operations → chosen relation → smallest action → protected dimensions → countercase → target inspection`. Do not require all fields as a runtime record. A settled repair should remain small.

Explain the positive operation before its failure diagnosis. Give numerical starting ranges only with explicit source/task/media/script limits and an override condition. A source-specific rule is not a universal rule. Where necessary source support is absent, inspect a suitable primary passage before writing; label genuinely local synthesis instead of attributing it to a source family. Add no live-fetch dependency for stable craft reasoning. Scope any required current external verification to the actual claim.

Preserve supplied content, identity, permission and factual state; legitimate density, symmetry, conventions and defaults; optical exceptions; flat concern-driven loading; and separate design, implementation, human and provider evidence. No extra leaf, fixed expert count, hard token ceiling, style atlas, always-required worksheet, mandatory family count or universal grid/palette/timing rule is authorized by this plan.

## Source starting points and unresolved research

The audit's Q1-Q13 URLs and scoped readings are starting evidence, not automatic admission. Existing source families may be reused only where their actual scope covers the new rule; update the canonical source/rule mapping rather than inventing parallel registries.

Apply ADR-0003 and ADR-0019 before runtime admission. Record the exact intended use and source restrictions in the existing research ledger and non-routed source index, with the consequential rule mapped to its supporting passage or bounded local rationale. Prefer already admitted, adequately supporting sources. Classify contemplated external artifacts as public fixture, local evaluation only or method/reference only; unknown permissions stay method/reference only. Keep restricted expression closed while authoring from scoped claim notes, then screen independently worded output. Reference-only sources may be inspected and cited: their status does not forbid a supported, scoped attributed recommendation, but it does forbid packaging or adapting their protected expression/assets under this policy. Do not relabel an external prescription or numeric range as local synthesis to bypass provenance. Butterick's ranges, IBM/Carbon system rules and other audit examples remain provisional until this source/use check; omit unnecessary numbers instead of inventing universal authority. No copied source fixture is needed for the original examples planned here.

- Composition/type/colour: Q1-Q4 support selected fundamentals; no universal line-length, leading or colour-count claim follows. Optical type-size matching is a separate declared comparison question, not uncontrolled normalization.
- Image/form: Q5-Q6 and Q10-Q11 supply concrete bounded examples and technical operations. Inspect additional sources for optical principles or repeat construction when the cited passages do not support them. Brand construction rules cannot silently become general Mark rules.
- Information/diagram: Q7-Q9 offer form/layout families. Do not adopt the line-chart-for-time-only wording; ordered non-temporal domains are a legitimate countercase.
- Web/motion: Q12-Q13 demonstrate operational selection. Do not import example viewport sizes, system-specific timings or prohibitions.
- Cartographic label/generalization craft, the chosen historical style example and specific explanatory/optical prescriptions not covered by inspected passages need targeted source work before adoption. A new source review must not be reported as already completed.

## Evaluation protocol to freeze before implementation

1. Record the actual intended execution model and effort, toolset, renderer and applicable installed partners. Follow current explicit user settings; do not carry an old model override from another Plan into this one. If the target is not established, resolve it before provider execution. The Astra/Fable plan-review settings are not design-test settings.
2. In W-001 freeze exact task inputs, authoritative fixtures and source models, protected content, every mapped candidate-independent subquestion, countercases, playback contracts, geometry/content manifests and final combined transfer inputs before runtime edits. Store an immutable source and built baseline. Fresh evaluation content must differ from packaged teaching examples. Keep one complete preserved baseline available through all Work Items. Later items consume these evaluation inputs; authoring separate teaching examples later does not reopen their definition. If an evaluation input proves defective, preserve the original record and explicitly invalidate only the affected comparison before freezing a new case revision.
3. For each PG-01-PG-16 family, define the positive task and legitimate countercase and every mapped subquestion. PG-16 may use several small independent fixtures; it must not force all seven retained leaves into one artificial task. Applicable modules are selected through Core by the actual concern. The PG-01–PG-16 namespace is separate from the existing modules.yaml C01–C22 common-load IDs; case labels are test organization, not a new router. For the seven unchanged owners, use targeted regression evidence only where changed additions touch their boundary; preserve unaffected existing evidence.
4. Freeze each row's evidence tier in W-001. For P1 additions use matched baseline/candidate trials; a proposed Core change also needs a demonstrated baseline gap and a useful candidate difference before retention. For P2 teaching additions, candidate application plus a legitimate countercase can establish bounded sufficiency; run a baseline as well whenever claiming improvement, attributing a suspected regression, or deciding whether a new behavior is needed. Shared cases may carry both tiers but score each subquestion separately. Baseline execution precedes the first corresponding candidate result; conditions, model/effort, task content, renderer, permissions and evidence availability match. Define candidate exposure, evaluation order and comparison method before results. A P2 candidate-only result supports no comparative claim. One run is development evidence, not statistically established improvement.
5. Generation must create the requested editable artifact. Critique is read-only. Repair starts from the same supplied defective source, preserves its successful relations and re-renders the affected contexts. Distribute these operations across families according to their actual mechanism; each retained technique needs evidence of application and discrimination, not merely the added phrase in output. Define application as a locatable artifact relation or operation that addresses the predeclared variable: generation demonstrates it in the result; repair shows the relevant source-to-output change while protecting successful relations; critique identifies the exact source location and an actionable correction without mutating it. A justified no-change countercase can pass; technique names and persuasive explanations alone cannot.
6. Name the evaluator and review method during W-001. Inspect artifacts under neutral identifiers before reading the model explanation or module-read trace; hide arm labels when practical. Score exact content, semantic parity, concrete action, visual effect, preservation of legitimate defaults/exceptions, route ownership, source handling and unnecessary overhead separately. Self-assessment is labelled as such and does not count as independent validation; an additional provider/evaluator is not automatically required. A render does not prove comprehension, native script quality, legal clearance, runtime behavior or physical acceptance. Capture only the lanes the concrete task needs and mark applicable missing lanes unverified.
7. Preserve every original valid result, failure and material disagreement. Diagnose capture/infrastructure failures separately. Do not rerun an unchanged valid unfavourable output until it improves or increase a budget after a provider rejection. A changed candidate receives an explicit new revision and affected-case record; historical outputs remain intact.
8. Use actual artifacts for the final combined transfer and quiet-utility comparison. Use the inputs frozen in W-001, separate from the teaching examples and per-module tuning cases; do not edit a case's interpretation after seeing preferred output. Technical checks and model agreement cannot replace visual or task evidence.

Numbers of examples, modules per case, and provider calls are not quality gates. Estimate and record necessary effort; split overlarge cases where it improves interpretable evidence. Existing confidentiality, safety, parity and outcome-preservation controls remain binding.

## Dispositions and completion

Every row receives an outcome record in the later implementation evidence: `retained with evidence`, `revised with evidence`, `not added because already sufficient`, or `blocked/unverified`. Keep exact source and case references plus the reason, evidence tier and evaluator limits. For blocked/unverified rows, name the missing evidence or capability, concrete next action and owning Work Item. Report disposition counts as bookkeeping, never as a quality score. No proposed module improvement disappears merely because it was P2 or inconvenient.

Retain a proposed addition when it supplies the intended operation or improves a predeclared discrimination/repair outcome and preserves the protected floors. If baseline already performs the task adequately and the added instruction supplies no useful distinction or worsens scope/behavior, omission is allowed with the concrete comparison and a precise explanation. For a P2 proposal that only illustrates an existing explicit operation, an exact existing-source locator and reason may establish 'already sufficient'; this is a documentation judgment, not proof of model performance. Candidate-only success cannot prove baseline sufficiency. In either case, that fulfills the audited question rather than pretending a defect existed. Do not use omission to hide an unresolved real capability gap. A required gap that remains unresolved leaves the owning Work Item incomplete. An omitted rule's sample may remain development-only when useful, but it is not packaged as a mandatory runtime example; record it as a sample location alongside the row's disposition, not as a fifth success category.

The completed local package requires traceability for all rows, useful retained guidance, preserved boundaries, passing scoped technical checks and honest output evidence. Lack of proof for a claim blocks that claim; it does not authorize simulated proof. No broad superiority, independent qualification or all-domain professional competence claim follows from this work.
