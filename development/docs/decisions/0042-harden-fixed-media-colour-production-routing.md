# Harden fixed-media, colour and production routing from public ownership

## Decision

Accepted automatically under the user's standing instruction to accept project
decisions: make one narrow, public-contract-derived Core clarification. For
fixed-media work, select Colour when reproduction decisions are open and Media
Production when export, preflight or provider-handoff decisions are open;
eventual delivery alone selects neither.

This clarification follows the existing public owner records and direct module
labels. It does not use or claim to explain private Canary 1 facts. Keep all
three experts flat and directly selected; introduce no dependency, chain or
automatic bundle. Add deterministic positive and negative route fixtures for
fixed-media-only, fixed-media plus reproduction, fixed-media plus handoff, the
exact three-owner conjunction and eventual-delivery-only boundaries.

After all package, route, generated-index, Design/UI boundary, source-link and
Skill Creator gates pass, run a new source-cleared public stress regression with
an indirect three-owner brief and negative controls. Only then rebuild the
executable package manifest and prepare a fresh qualification-v7 zero-call
suite. qualification-v6 remains failed historical evidence and no v6 artifact
is reused as a passing score.

## Problem

The unchanged package passed the explicit ADR-0038 public three-owner fixture,
so the sealed one-of-three result was not reproduced and cannot by itself
justify a private-case patch. The public owner contracts nevertheless leave a
cross-owner discoverability risk: fixed-medium intent can dominate routing even
when independent reproduction and delivery decisions are also open. A concise
Core boundary can reinforce existing ownership without exposing private facts
or creating unconditional co-selection.

## Drivers

- Derive the change from inspectable public module ownership.
- Reinforce all-materially-applicable multi-select behavior.
- Avoid an unconditional three-expert bundle and over-routing.
- Preserve settled and eventual-delivery negative boundaries.
- Keep Core growth minimal and expert topology flat.
- Require public stress evidence and fresh sealed qualification.

## Considered alternatives

- Make no package change and generate v7 immediately. Rejected because the
  only sealed behavioral failure would remain entirely unaddressed.
- Add an unconditional Editorial-to-Colour-to-Production dependency. Rejected
  because it violates direct routing and over-reads ordinary fixed media.
- Encode a private case phrase or artifact pattern. Rejected because it leaks
  holdout information and overfits.
- Expand every route label with cross-domain combinations. Rejected because the
  observed risk is narrow and Core already owns multi-select orchestration.
- Treat the ADR-0038 public pass as product qualification. Rejected because it
  is one source-cleared falsifier, not a sealed suite.

## Consequences

- Core changes by one compact routing sentence; expert files and ownership do
  not change.
- The Design executable manifest changes and all prior package manifests remain
  historical.
- Future sealed execution requires a new v7 runner manifest, fresh source-cleared
  cases, fresh canaries and explicit execution authorization.
- Public stress failure stops before v7 generation and permits only the smallest
  demonstrated correction.
- qualification-v6 remains failed regardless of future outcomes.
- Publication, installation, commit, push, tag and release remain unauthorized.
- W-005 was already in progress, so its immutable `Decisions` list cannot add
  ADR-0042; mutable Evidence records the change and validation.

## Confirmation

Confirm the exact one-sentence Core diff, direct flat routes, positive and
negative fixtures, no generated-index drift, package and boundary validation,
new manifest hash, public stress exact reads and forbidden-read absence, no
private facts in public inputs, zero v6 continuation and zero sealed calls before
fresh v7 authorization.

## Revisit when

The public stress case over-routes or under-routes, token or package gates fail,
owner boundaries change, v7 model-free readiness finds a contract defect, or a
different sealed failure family appears.
