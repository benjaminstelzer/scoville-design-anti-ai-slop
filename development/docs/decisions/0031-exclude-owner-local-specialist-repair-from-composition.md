# Exclude owner-local specialist repair from Composition

## Decision

Recommended and accepted under the user's standing authorization to accept
Plan Decisions automatically: add one narrow negative boundary to the Core
Composition route. When an already selected specialist system owns the work
and only a local label collision remains, Composition is not selected if the
general hierarchy, grouping, spacing, negative space, grid, reading order and
content fit are settled.

Add one model-free direct-route regression for a route-integrated physical
wayfinding map whose topology, destination hierarchy, sign system and general
composition are settled but whose specialist label placement still collides.
The required route is Physical Wayfinding plus Cartography; Composition is
forbidden. Preserve every existing positive Composition signal and every
specialist ownership rule.

Build a new executable package manifest after deterministic validation. Do
not mutate the v3 candidate manifest or qualification-v4. Create a new
qualification-v5 suite and use a distinct original public Wayfinding case to
test the corrected package with the same exact Terra High, parent renderer,
arm parity and maximum Call-A/B/C mechanism. The old v4 public case remains
failed development evidence and is not retried or promoted.

This Decision authorizes the local package edit, deterministic tests, v5
suite creation and bounded public open canary. It does not authorize unsealing
holdout content, a real sealed call, publication, installation, commit, push,
tag or release.

## Problem

The v4 public canary proved that the three-call parent-render loop can produce
a clean final artifact in both arms, but Design Call C loaded Composition for
one remaining node-label position inside an already selected Wayfinding and
Cartography system. The descriptor's general hierarchy, route model, grid and
fit were settled. The extra route therefore failed the frozen route gate even
though the final render passed.

The current Core excludes Composition for Web-owned responsive pressure and
Packaging-owned panel or pack hierarchy, but it does not state the general
owner-local specialist-repair boundary. Repeating v4 unchanged would spend
calls without changing the demonstrated cause, while broad Composition
suppression would damage valid multi-domain routing.

## Drivers

- Repair only the demonstrated routing cause.
- Preserve Composition for genuinely open within-frame structure.
- Keep specialist-local repair with the specialist owner.
- Prove the rule model-free before further provider use.
- Avoid training or qualifying on the already observed v4 case.
- Preserve failed evidence and suite identity immutability.

## Considered alternatives

- Accept the clean render despite the extra route. Rejected because route and
  visual gates were frozen separately before execution.
- Retry v4 with a more explicit task prompt. Rejected because it would alter
  the observed condition and overfit a used public case without changing the
  package cause.
- Forbid Composition whenever a specialist is selected. Rejected because
  specialist work can still have a separately open general hierarchy, grid,
  spacing or fit concern.
- Put the exception only in Wayfinding or Cartography. Rejected because the
  missing boundary is a Core selection rule and can recur in other specialist
  systems.

## Consequences

- Core gains one short negative-routing clause and must remain within its
  existing token ceiling.
- Direct route fixtures gain one owner-local specialist-repair case.
- The changed package requires a new manifest and suite identity.
- A distinct public case costs two to six Terra High calls under equal arm
  eligibility; unused calls disappear.
- Passing W-023 proves only this public mechanism and route regression. It
  does not authorize or substitute for sealed qualification.

## Confirmation

Confirm with the new route fixture; all existing direct and successor-v2 route
contracts; package unit, schema, generated-index, source-link and token checks;
Design/UI boundary validation; Skill Creator validation; a new package
manifest; qualification-v5 synthetic tests and zero-call preflight; and a
distinct public Terra High arm-parity canary whose Design arm never selects
Composition for the owner-local repair.

## Revisit when

The rule suppresses Composition despite a separately open general layout
concern, another specialist-local repair produces a different over-read, the
Core exceeds its token ceiling, the v5 harness changes parity semantics, or
the user changes model or execution authorization.
